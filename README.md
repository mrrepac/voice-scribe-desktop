# Voice Scribe для Windows

Отдельное приложение для локальной диктовки: поставьте курсор в текстовое поле,
нажмите **Ctrl+Space**, скажите фразу и завершите запись. Voice Scribe распознает
речь на компьютере и вставит результат в исходное окно через буфер обмена.
Приложение работает в системном трее; Obsidian для него не нужен.

## Выпуск новой версии

1. `npm version patch` (или `minor`) повышает версию, создаёт коммит и тег.
2. `git push origin main --follow-tags` отправляет изменения и запускает Windows release.
3. Workflow проверяет типы и тесты, собирает Setup, загружает установщик,
   `.blockmap` и `latest.yml` в черновик GitHub Release, затем публикует его.

Установленные приложения получают только опубликованные релизы. Не заменяйте
установщик уже выпущенной версии: для исправлений выпускайте следующий номер.
Сборки пока не подписаны сертификатом издателя; Windows может показать предупреждение
SmartScreen при первой установке.

Механизм обновлений: [electron-updater и NSIS](https://www.electron.build/v26/docs/features/auto-update/).
Токен GitHub нужен только workflow, в приложение он не включается.

## Запуск

Для обычной работы скачайте **Voice-Scribe-Setup-…-x64.exe** из
[последнего релиза](https://github.com/mrrepac/voice-scribe-desktop/releases/latest).
Установщик добавляет приложение в меню «Пуск» и на рабочий стол, устанавливает
его для текущего пользователя и не требует прав администратора.
Если старая portable-версия сейчас обрабатывает аудио, сначала дождитесь результата
и выберите **«Выход»** в трее, затем запускайте установщик.
История, настройки, зашифрованные ключи и загруженные модели упакованной версии
остаются в прежнем каталоге данных. Версия для разработки хранит данные отдельно.

Установленная версия проверяет GitHub Releases после запуска и раз в шесть часов,
когда приложение не занято. Новая версия загружается в фоне. Появится кнопка
**«Перезапустить и обновить»**; во время записи и обработки она недоступна.
Обычное закрытие или выход не устанавливает обновление автоматически.
В **Настройки → Обновления** можно проверить наличие новой версии вручную.
Portable-версия и запуск из исходников не обновляются автоматически.

Для запуска из этой папки:

1. Откройте **Start-Voice-Scribe.cmd** в этой папке. Если готовая сборка есть в
   `release/win-unpacked`, запустится она. Иначе запускается версия из исходников
   при наличии установленных зависимостей.
2. В настройках выберите микрофон и язык. Нажмите **«Подготовить модель»**:
   при первом использовании нужные файлы загружаются с Hugging Face.
3. Поставьте курсор в нужное приложение и используйте Ctrl+Space. Оставьте
   исходное окно активным до появления текста.

Для готовой сборки Node.js устанавливать не нужно. Можно также открыть
`release/win-unpacked/Voice Scribe.exe` напрямую; папку `win-unpacked` нужно
переносить целиком. `npm run dist` создаёт установщик Setup, а
`npm run dist:portable` — отдельный portable EXE в `release`.
Закрытие основного окна оставляет приложение в трее. Для завершения
работы выберите **«Выход»** в меню значка.

## Горячие клавиши

| Сочетание | Действие |
|---|---|
| Короткое Ctrl+Space | Начать запись; следующее нажатие — закончить и вставить текст |
| Удерживать Ctrl+Space | Записывать до отпускания любой клавиши сочетания; порог удержания — 350 мс |
| Ctrl+Shift+Space | В другом приложении — обычная вычитка и вставка без Enter; в Scribe — вычитка с отчётом |
| Escape | Отменить текущую запись, обработку или ожидающую вставку |
| Ctrl+Alt+V | Вставить последнюю расшифровку в текущее окно |

Обычный Enter остаётся клавишей текущего приложения. Вычитка не нажимает Enter. Escape
перехватывается только во время активной сессии и без дополнительных модификаторов.

Сочетание для диктовки выбирается в **Настройки → Микрофон и диктовка**: Ctrl+Space
(по умолчанию), Ctrl+Alt+Space или левые Win+Alt. Вычитка — то же сочетание с Shift.
Ctrl+Space перехватывается всегда и мешает автодополнению в VS Code и JetBrains; при
другом выборе оно возвращается этим программам. В режиме Win+Alt клавиши не
блокируются: Voice Scribe не даёт им открыть «Пуск» или меню приложения, а если
следом нажата третья клавиша (например, Win+Alt+R для записи экрана), начатая
запись тихо отменяется и сочетание Windows срабатывает как обычно. Ctrl+Alt+V и
Escape не меняются.

Кнопка микрофона в самом Voice Scribe и запись из меню трея дают текст в буфере
обмена. Для автоматической вставки во внешнее приложение начинайте запись
горячей клавишей из нужного поля.

## Возможности

- Русский и другие языки Whisper, автоопределение и пара языков для чередующихся фраз.
- Вычитка текста через настраиваемый API языковой модели, с возвратом исходного варианта.
- Выбор микрофона, остановка после паузы, звуковые сигналы и подготовка модели при запуске.
- Голосовые знаки препинания и словарь замен: например, `войс скрайб = Voice Scribe`.
- Запоминание исправлений из редактора текста и субтитров: проверьте предложенную
  пару и сохраните её в словарь для следующих расшифровок.
- Предпросмотр по фразам во время записи. Во внешнее поле текст вставляется один раз,
  после завершения; предварительный текст может меняться.
- История с лимитом 100, 500, 1000 или 5000 обычных записей, закреплением,
  поиском, копированием и экспортом всей истории. Закреплённые записи не входят
  в лимит; уменьшение лимита применяется при следующей новой расшифровке.
- Расшифровка аудио и видео размером до 250 МБ и длительностью до двух часов: перетащите файл в окно или нажмите
  **«Открыть файл»**. Перед запуском укажите число ораторов или оставьте поле пустым.
  Встроенный FFmpeg извлекает первую звуковую дорожку локально во временный файл.
  Whisper читает фрагменты до 30 секунд, разрезанные в паузах, с исходными таймкодами. Временное аудио
  удаляется после завершения, ошибки или отмены; остатки после аварии — при запуске.
  Для двух часов нужно до 440 МиБ свободного места. Определение ораторов по-прежнему
  анализирует всю запись в отдельном процессе и может потребовать заметный объём памяти.
- Таймкоды фраз в аудиофайлах, редактирование текста субтитров и экспорт SRT/VTT.
  Таймкоды и исправления сохраняются в истории вместе с именем исходного файла.
- Запуск вместе с Windows для упакованной сборки. Папка приложения должна оставаться
  по выбранному пути.

## Подключение языковой модели

В разделе **Настройки → Вычитка через API** включите подключение, укажите базовый
адрес сервера (например, `https://api.openai.com/v1` или `http://localhost:1234/v1`)
и точное имя модели у провайдера. Введите API-ключ и нажмите **«Сохранить ключ»**.
Для локального сервера без авторизации ключ можно не задавать. Адрес должен
поддерживать [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create):
приложение добавляет `/chat/completions` к базовому адресу.

В списке провайдеров есть ChadGPT, GPTunnel, Polza AI, DeepSeek, OpenAI, Ollama
и LM Studio; «Свой адрес» позволяет подключить другой совместимый сервер.
Выбирайте именно сервис, выдавший ключ: ключ посредника не подходит к серверу OpenAI.
Ключи зашифрованы и привязаны к базовому адресу, при переключении на другой сервис
они не отправляются чужому серверу. Старый ключ при обновлении привязывается к
ранее настроенному адресу. Если адрес был неверным, сохраните ключ заново под правильным.
Нажмите **«Получить модели»**, выберите модель из каталога и нажмите
**«Проверить модель»**. Последняя кнопка отправляет короткий тестовый текст —
это обычный запрос по тарифу провайдера. Каталог сам по себе не гарантирует,
что баланс и права позволяют выполнить генерацию.

Начните диктовку через Ctrl+Space и завершите через **Ctrl+Shift+Space**.
Если сочетание нажато в другом приложении, модель выполняет обычную вычитку,
исправляя ошибки распознавания по контексту переданного текста. Чистый результат
вставляется в исходное поле без Enter, без отчёта и пометок. Содержимое чужого окна
не читается. Вне активной записи сочетание в другом приложении не перехватывается.
В окне Scribe сочетание или кнопка **«Вычитать»** запускает режим проверки с
показом изменений и сомнительных мест. Такой результат остаётся в Scribe и не
вставляется автоматически в другое приложение. **«Вернуть исходный»**
восстанавливает текст в редакторе; внешнюю вставку можно отменить в целевом приложении.
Фразы с таймкодами вычитываются группами до 24 фраз с соседним контекстом.
Идентификаторы проверяются перед применением ответа; времена и ораторы сохраняются.
Если модель пропустила или добавила фразу, исходный текст остаётся без изменений.
После вычитки в режиме проверки над редактором появляется отчёт: удалённое зачёркнуто красным,
добавленное подчёркнуто зелёным. Неоднозначные места, отмеченные моделью,
показаны жёлтым с пояснением и кнопкой **«Найти в редакторе»** для ручной правки.
Модель получает инструкцию не угадывать исправления без контекста. Замечания
могут быть неполными; если провайдер вернул только текст, приложение сообщает,
что проверка неоднозначности недоступна. При ручном редактировании отчёт помечается
устаревшим. Он относится к последней вычитке в текущем окне и не сохраняется в истории;
в историю, буфер и экспорт попадает чистый исправленный текст.
При ошибке изменения не применяются. Для неудавшейся вычитки диктовки исходный
текст сохраняется в редакторе, истории и буфере вместо автоматической вставки.

На сервер уходит только текст по явному запросу вычитки, без аудио и истории.
Ключ хранится отдельно от настроек в `api-key.enc`, зашифрованном средствами Windows.
При смене провайдера замените или удалите сохранённый ключ. Удалённые серверы требуют
HTTPS, HTTP разрешён только для localhost. Ограничение — 50 000 символов; время ожидания
растёт с длиной текста (от 1 до 10 минут на запрос); Esc отменяет ожидание (уже отправленный запрос может быть тарифицирован).
Распознавание Whisper по-прежнему локальное и не требует включения API.

## Таймкоды и субтитры

Нажмите **«Открыть аудио»** и выберите файл. После распознавания переключайтесь
между текстом целиком и фразами с таймкодами. Исправляйте текст в отдельных фразах:
полный текст и экспорт субтитров используют эти же исправления. Изменения
автоматически сохраняются в истории; запись можно открыть снова после перезапуска.
Кнопки **SRT** и **VTT** сохраняют субтитры в выбранный файл в кодировке UTF-8.

Время отсчитывается от начала исходного аудиофайла, включая тишину в начале.
Границы фраз определяет модель, поэтому таймкоды приблизительные. Если модель
не вернула пригодных таймкодов, приложение покажет обычный текст без экспорта
субтитров. Для старых записей истории таймкоды можно получить, заново открыв
исходный аудиофайл. Микрофонная диктовка сохраняет прежний режим работы.

## Определение ораторов в аудиофайлах

При открытии аудиофайла приложение автоматически определяет разные голоса и
добавляет метки **«Оратор 1», «Оратор 2»**. Номера назначаются по первому появлению
голоса в пределах файла; личности людей и голоса из других записей не узнаются.
Для отключения используйте **«Настройки → Распознавание → Определять ораторов
в аудиофайлах»**. На микрофонную диктовку настройка не влияет.

Метки видны в режиме **«Таймкоды»**. Поле под таймкодом позволяет исправить имя
оратора сразу во всей расшифровке, в том числе в уже сохранённой истории.
Если один голос получил несколько меток, задайте им одинаковое имя для объединения.
«Не определён» и «Несколько ораторов» меняются только у выбранной реплики.
Метки и правки сохраняются в истории и входят в копируемый текст, TXT, SRT и VTT.
Перед обработкой можно указать число голосов (1–50), выбрать автоматическое
определение (пустое поле) или отключить метки для этого файла.
Чтобы заново разделить голоса с другим числом ораторов, откройте исходный файл ещё раз.

Первое использование загружает около **107 МБ** дополнительных моделей.
Анализ выполняется локально на процессоре; Python и аккаунт Hugging Face не нужны.
Модели хранятся в каталоге данных приложения, в `models/speakers`.
После загрузки моделей интернет не нужен. Определение ораторов поддерживает
записи до двух часов. Esc отменяет обработку; если анализ ораторов завершился
ошибкой, уже распознанный текст всё равно сохраняется с пояснением.

Количество голосов и границы реплик приблизительные. Шум, короткие реплики,
похожие голоса и одновременная речь могут приводить к ошибкам. Метка назначается
по пересечению интервалов речи с таймкодами Whisper. Фрагменты без определённого
голоса помечаются **«Не определён»**, а без явно преобладающего голоса —
**«Несколько ораторов»**: автоматического разделения текста внутри такой фразы нет.
Если Whisper не вернул таймкоды, остаётся обычный текст без меток.

## Запоминание исправлений

Исправьте слово или короткую фразу в редакторе, затем нажмите
**«Запомнить исправление»**. Проверьте поля **«Распознано»** и **«Писать как»**
и нажмите **«Запомнить»**. Можно также выделить ошибочную фразу и заполнить
замену вручную. Для субтитров исправляйте текст внутри нужного фрагмента.

Сохранённое правило применяется к следующим расшифровкам — и диктовкам,
и аудиофайлам. Приложение не запоминает правки без этого действия.
Правило остаётся после перезапуска; его можно изменить или удалить в
**«Настройки → Ваш словарь»**. Повторное сохранение той же исходной фразы
обновляет правило. Это словарь текстовых замен после распознавания;
переобучение модели и интернет не требуются.

## Модели и данные

Режим **«Авто»** выбирает Whisper Turbo на WebGPU и Small на процессоре/WASM.
Для Turbo на GPU используются веса q4 — около **724 МиБ**, плюс небольшие файлы
конфигурации. **Turbo HQ** берёт те же веса, но энкодер в fp16 — около **1,5 ГиБ**;
на видеокартах с поддержкой shader-f16 она заметно быстрее обычной Turbo. Без shader-f16
Turbo HQ работает на файлах обычной Turbo. При отказе WebGPU автовыбор переходит на Small/WASM; для этого
могут понадобиться другие файлы модели. Tiny и Base требуют меньше памяти.
Первое распознавание включает загрузку модели в память и может занять больше времени.

Аудио обрабатывается локально и не отправляется на сервер. Приложение не сохраняет
микрофонные записи в аудиофайлы. Готовый текст сохраняется в истории и остаётся
в системном буфере обмена. После полной загрузки выбранной модели распознавание
работает без интернета.

Точный путь к данным показан в **«Настройки → Приложение»**. Упакованная версия
использует каталог профиля пользователя Windows внутри `%APPDATA%`; portable EXE
тоже хранит данные профиля отдельно от исполняемого файла. Версия для разработки
использует `.data` в папке проекта, проверочный запуск — `.data/smoke`.
В каталоге данных находятся `settings.json`, `history.json` и собственная папка `models`.
Настройки и история имеют резервные копии `.bak` предыдущего сохранения.
При повреждении приложение восстанавливает копию, сохраняет оригинал в `.corrupt`
и показывает сообщение. Если исправной копии нет, сохранение блокируется, чтобы
не затереть исходные данные. После явной очистки резервная копия истории тоже
обновляется, поэтому удалённые записи не возвращаются при восстановлении.

В истории кнопка **«Закрепить»** защищает запись от вытеснения новыми расшифровками.
При очистке можно оставить закреплённые записи и сначала экспортировать всю историю
в TXT. Отмена экспорта отменяет удаление. Уже сохранённые повреждённые оригиналы
`.corrupt` автоматически не удаляются.

Для повторного использования уже загруженных моделей приложение также читает
`%LOCALAPPDATA%\voice-scribe\models` — кэш исходного плагина. Этот каталог
используется только для чтения; новые модели сохраняются в собственный каталог
данных. Очистка истории удаляет текстовую историю приложения, но не системный
буфер обмена и не модели.

## Если текст не вставился

Вставка происходит через Ctrl+V, когда исходное окно всё ещё активно. Voice Scribe
не переключает фокус обратно. Если вы перешли в другое окно, держите модификаторы
или Windows блокирует ввод, результат остаётся в буфере обмена: вставьте его вручную.

Проверяется окно, а не конкретное поле внутри него. До завершения не переносите
курсор в другое поле или вкладку того же окна. Программы с правами администратора,
защищённые поля, игры и терминалы с другим сочетанием для вставки могут требовать
ручной вставки. Принятый Windows Ctrl+V не гарантирует, что приложение вставило текст.
Enter отправляется только после принятой последовательности вставки и повторной
проверки активного окна.

Если микрофон недоступен, проверьте выбранное устройство и разрешение Windows
на доступ классических приложений к микрофону. При остановке службы горячих клавиш
приложение делает до трёх попыток восстановления. Если они не помогли, нажмите
**«Подключить заново»** в **Настройки → Приложение**. Если сочетание запускает одновременно
плагин в Obsidian, отключите соответствующее сочетание в одном из приложений.

## Разработка

Нужны Windows, Node.js 22 или новее и доступ к npm. Для нативного помощника
используется компилятор .NET Framework 4.x, установленный в Windows; отдельный
.NET SDK не требуется.

```powershell
npm install
npm run typecheck
npm test
npm start
```

`Start-Voice-Scribe.cmd` умеет находить Node.js в стандартной папке установки
`Program Files\nodejs`, даже если команда `node` отсутствует в PATH.
Он не устанавливает зависимости автоматически.

```powershell
npm run build       # приложение и нативный помощник
npm run pack        # release/win-unpacked
npm run dist        # установщик Setup с автообновлением
npm run dist:portable # отдельный portable EXE
powershell -NoProfile -ExecutionPolicy Bypass -File tests/native-smoke.ps1
```

Проверка нативного протокола не меняет буфер обмена и не посылает клавиши
в пользовательские приложения. Для проверки интерфейса и реального ASR:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests/native-fixture.ps1
node scripts/build.mjs --smoke
.\node_modules\electron\dist\electron.exe . --smoke-test
.\node_modules\electron\dist\electron.exe . --smoke-test --design-test
.\node_modules\electron\dist\electron.exe . --smoke-test --subtitles-test
.\node_modules\electron\dist\electron.exe . --smoke-test --corrections-test
.\node_modules\electron\dist\electron.exe . --smoke-test --history-test
.\node_modules\electron\dist\electron.exe . --smoke-test --speakers-test
.\node_modules\electron\dist\electron.exe . --smoke-test --asr-test
```

Последний вариант распознаёт синтезированный тестовый WAV и может загрузить
модель. Результаты находятся в `artifacts`. Генерация WAV требует установленного
английского голоса Windows и не воспроизводит речь через динамики.

Интерфейс автоматически следует светлой или тёмной теме Windows и учитывает
системную настройку уменьшения анимации. Флаг `--design-test` проверяет геометрию
интерфейса в обеих темах при обычном и минимальном размере окна, сохраняет
скриншоты и отчёт в `artifacts/design`. Снимки с `fixture` в имени показывают
тестовые состояния интерфейса и не запускают запись или загрузку моделей.

Основные части: `src/main` — Electron, хранение и вставка; `src/renderer` —
интерфейс и сессии; `src/asr` — локальный Whisper в worker; `native` — помощник
Windows с глобальными сочетаниями. Протокол описан в `native/README.md`.

Основа распознавания перенесена из Voice Scribe 0.4.1 для Obsidian, автор mrrepac,
лицензия MIT. Исходный плагин в `D:\claudeworks\plugins\voice-scribe` не изменён.
Лицензии компонентов перечислены в `THIRD_PARTY_NOTICES.md`.

Проверка `--speakers-test` использует `artifacts/speakers/two-speakers.wav` —
[публичный пример двух голосов sherpa-onnx](https://huggingface.co/csukuangfj/speaker-embedding-models/resolve/0743f301363dec56491a490f6d6cbc9d67f9a3bf/1-two-speakers-en.wav).
Проверяет настоящий импорт аудио, Whisper, двух и одного оратора, тишину, отмену,
правку меток и повторное открытие истории. Нужны кэш выбранной модели Whisper и
модели ораторов (последние загружаются, если их нет). Отчёты и снимки — в `artifacts/speakers`.
